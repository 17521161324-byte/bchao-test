# ASR 外部豆包与本地 Qwen 对比报告

日期：2026-08-03  
数据来源：`backend/data/bchao.db` 历史 ASR、ASR 转化评估、人工标记记录

## 一、结论摘要

当前结论是：**豆包仍是效果基线，本地 Qwen ASR 暂不适合直接替代豆包进行大范围部署。**

Qwen 的接口调用成功率较高，但历史数据已经显示出数字、左右侧归属、卵巢大小和部分业务片段漏识别问题。前置规则目前只能完成格式标准化，无法恢复 ASR 已经漏掉的语音；LLM 也不能稳定弥补缺失内容。

因此目前应采用：

```text
豆包 ASR：外部效果基线/对照
Qwen ASR：本地候选生产模型，继续评估
规则引擎：处理高置信度格式转换
LLM：只处理规则无法确定的字段
```

## 四、已暴露的主要问题

### 1. ASR内容缺失或数字错误

历史转换记录中已经出现：

- `0×38`：第一维数字识别异常；
- `33cm`：尺寸与单位混在一起；
- `14.413`：相邻数字被错误拼接；
- 左右卵巢或卵泡内容缺失；
- 同时说话时，部分医学术语被过滤。

这类问题发生在ASR或音频阶段，规则和LLM无法可靠恢复原始语音内容。

### 2. 规则过度转换

当前规则主要集中在数字格式化和片段转换，自动处理比例很高，但很多数字的业务归属并不确定。若规则强行转换，可能把：

- 闲聊数字变成卵泡；
- “乘一”错误转换成尺寸的一维；
- 口语化“这边”误判为左右定位；
- 备注内容误并入卵巢大小。

### 3. LLM结构化错误

历史人工标记中，原因分布为：

| 原因 | 标记数量 |
|---|---:|
| LLM提取错误 | 30 |
| ASR/收音问题 | 25 |
| 提示词规则不足 | 4 |
| ASR数字识别错误 | 4 |
| 其他/未填写 | 14 |

LLM错误数量较多，但其中一部分是由于输入ASR本身已经缺词或数字错误，不能全部归因于提示词。

## 五、外部豆包与本地 Qwen 的判断

### 豆包 ASR

- 优点：已有较多历史数据和人工对照，适合作为当前效果基线；
- 缺点：存在调用失败、部分分段失败和多人同时说话时漏识别；
- 结论：当前可作为对照基准，但也不是绝对正确答案。

### 本地 Qwen ASR

- 优点：接口调用稳定，70条历史结果均返回成功；
- 缺点：业务数字、左右归属、卵巢尺寸和长文本完整性仍需验证；
- 结论：接口稳定性已经达到候选条件，但业务识别准确性尚未达到生产替代条件。

## 六、最终部署判断

当前不建议直接采用“Qwen ASR → 规则 → LLM”作为无人工干预的生产链路。

目前更适合的部署状态是：

1. 豆包作为外部基线，用于对照和异常复核；
2. Qwen作为本地候选模型，继续在固定金标准数据上测试；
3. 规则只自动处理高置信度数字和医学术语标准化；
4. 左右归属、尺寸异常、疑似漏词统一进入复核状态；
5. LLM不得根据常识补写未在ASR中出现的数字；
6. 只有在Qwen与专家标准ASR的业务字段召回率稳定后，才考虑大范围替换豆包。

## 七、报告限制

本报告使用的是当前数据库历史记录。由于存在重跑记录、未绑定批次记录、专家标准文本不完整和大量`pending`人工判断，本报告用于判断当前技术状态，不作为最终模型准确率验收报告。
