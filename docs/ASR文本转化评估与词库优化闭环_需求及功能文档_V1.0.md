# ASR文本转化评估与词库优化闭环需求及功能文档

> 文档版本：V1.0
> 编制日期：2026-07-27
> 适用场景：辅助生殖卵泡监测、超声检查、取卵、移植及相关诊疗语音转写
> 文档状态：待产品、研发、测试及临床业务评审

---

## 1. 项目背景

当前系统通过ASR将辅助生殖诊疗过程中的语音转换为文本，再将ASR文本发送至LLM，提取内膜厚度、内膜分型、左右卵巢大小、卵泡数值、异常影像描述及诊疗医嘱等结构化字段。

现有ASR结果主要存在以下问题：

1. 医学专有名词识别错误，例如：
   - “肉卵巢”误识别自“右卵巢”；
   - “尾生欠军”误识别自“回声欠均”；
   - “芝麻”误识别自“麻醉”；
   - “动胚胎”误识别自“冻胚胎”。

2. 数字表达格式不统一，例如：
   - “九点二”与“9.2”；
   - “三九乘以三零”与“39×30”；
   - “六零三五”可能对应“60×35”。

3. 关键医学信息可能发生实质性错误，例如：
   - 5.2被识别为9.2；
   - 12.0被识别为30；
   - “无回声”被识别为“五回声”或“五毫升”；
   - “取消移植”被识别为“取消一支”。

4. ASR输出可能存在循环重复、整条未转写及字段归属不清等问题。

5. 当前后台已支持人工审核ASR，并可形成一份人工整理后的标准ASR，但人工审核结果尚未形成可持续复用的词库、规则及评估数据。

因此，本项目需要建设一套：

> **ASR原始文本 → 规则及词库转化 → 转化准确性评估 → LLM效果评估 → 人工审核反哺词库**

的持续优化闭环。

---

## 2. 项目目标

本项目分为两个递进目标。

### 2.1 第一目标：评估文本转化是否准确

系统需明确展示：

- 哪些内容经过了转化；
- 转化前是什么；
- 转化后是什么；
- 使用了哪条规则；
- 转化是否正确；
- 是否存在漏转；
- 是否存在不应发生的过度转化；
- 是否涉及数字、左右侧、否定词或医疗决策等高风险内容。

第一阶段重点不是追求“转化数量越多越好”，而是优先确保：

> **已执行的转化足够准确，不因规则处理引入新的医学错误。**

### 2.2 第二目标：评估转化对LLM的实际效果

当文本转化准确性达到要求后，系统需比较：

1. 原始ASR进入LLM后的结构化结果；
2. 转化后ASR进入同一LLM后的结构化结果；
3. 人工标准ASR进入同一LLM后的结构化结果。

通过字段级评估，判断：

- 转化后是否提升LLM字段准确率；
- 是否降低待复核率；
- 是否减少人工修改量；
- 方案C经过转化后是否接近方案A；
- 词库和规则是否具备生产价值。

## 3. 项目范围

### 3.1 本期范围

本期建设以下两个核心模块：

1. **ASR文本转化评估**
   - 展示原始ASR、转化后ASR、人工标准ASR；
   - 展示每个转化片段；
   - 判断正确转化、错误转化、漏转及过度转化；
   - 统计转化准确率、覆盖率及高风险错误。

2. **人工审核反哺词库**
   - 比较原始ASR与人工标准ASR；
   - 自动抽取纠错差异；
   - 形成候选词及候选规则；
   - 经人工审核后发布至正式词库；
   - 支持词库版本管理及效果回归。

### 3.2 后续范围

后续在转化准确性达到要求后建设：

- 原始ASR、转化ASR、标准ASR三路LLM评估；
- LLM结构化字段级对比；
- 规则版本效果比较；
- 人工工作量变化统计；
- 方案A与方案C的最终能力对比。

### 3.3 暂不纳入范围

第一期暂不建设：

- 通用医学知识图谱；
- 自动训练或微调ASR模型；
- 候选规则未经人工审核直接发布；
- 自动修改无法从原文追溯的真实数值；
- 复杂向量知识库；
- Synonyms直接参与实时自动替换；
- 多机构、多租户词库隔离；
- 完整BI分析平台。

## 4. 核心原则

系统设计必须遵守以下原则：

1. **数字不可猜**
   - 只能进行确定性的格式标准化；
   - 不得依据医学常识修改真实数字；
   - 所有最终数字必须能够追溯至原始文本。

2. **左右侧不可猜**
   - 左右卵巢、左右卵泡归属不明确时必须待复核。

3. **否定词不可猜**
   - “无、未见、不、取消”等表达不得静默纠正。

4. **临床决策不可猜**
   - 移植、取消移植、麻醉、血糖、药物剂量等高风险内容不得仅凭候选自动确认。

5. **所有转化必须可追溯**
   - 保留原始文本、转化文本、规则ID、规则版本、处理动作和人工审核结果。

6. **先验证转化准确，再验证业务效果**
   - 不以“文本变得更规范”作为上线依据；
   - 最终应以字段准确率和人工复核量作为效果依据。

## 5. 用户角色

### 5.1 ASR审核人员

负责：

- 查看原始ASR；
- 查看转化后ASR；
- 编辑并确认人工标准ASR；
- 对系统转化结果进行必要审核；
- 标记转化正确、错误、漏转或需回听。

### 5.2 词库管理员

负责：

- 审核系统自动生成的候选词及候选规则；
- 修改规则适用场景、上下文和处理动作；
- 决定规则是否进入正式词库；
- 生成词库版本；
- 查看规则发布前后的回归结果。

### 5.3 产品及算法评估人员

负责：

- 查看整体转化准确率；
- 查看不同规则版本效果；
- 查看高风险错误；
- 对比原始ASR、转化ASR和标准ASR的LLM结构化效果；
- 评估方案C能否接近方案A。

### 5.4 系统管理员

负责：

- 配置角色权限；
- 管理词库版本；
- 执行版本发布和回滚；
- 查看处理异常及任务日志。

# 7. 功能模块一：ASR文本转化

## 7.1 功能目标

在ASR输出与LLM处理之间增加一个医学文本标准化处理层，对确定性较高的格式和术语问题进行处理，对不确定问题生成候选和风险提示。

## 7.2 转化类型

### 7.2.1 数字格式标准化

系统应支持：

| 原始表达 | 转化结果 | 动作 |
|---|---|---|
| 九点二 | 9.2 | AUTO |
| 三九乘以三零 | 39×30 | AUTO |
| 十二毫米 | 12 mm | AUTO |
| C级、C 型 | C型 | AUTO |
| 六零三五 | 候选60×35 | CANDIDATE |
| 三六乘一点三四 | 候选36×34 | REVIEW |

### 7.2.2 医学术语标准化

系统应支持根据场景和上下文处理医学混淆词。

| 原始表达 | 标准表达或候选 | 动作 |
|---|---|---|
| 肉卵巢 | 右卵巢 | AUTO |
| 左两条大小 | 左卵巢大小 | AUTO |
| 尾生欠军 | 回声欠均 | AUTO |
| 芝麻 | 麻醉 | AUTO，限定取卵麻醉场景 |
| 动胚胎 | 冻胚胎 | AUTO |
| 五回声 | 疑似无回声 | REVIEW |
| 五毫升 | 疑似无回声 | REVIEW |
| 取消一支 | 疑似取消移植 | REVIEW |

### 7.2.3 基础文本清洗

系统应支持：

- 删除无效ASR标签；
- 清除异常空格；
- 识别连续重复片段；
- 对循环输出进行截断；
- 恢复基础标点；
- 保留原始文本不被覆盖。

## 7.3 转化处理等级

| 等级 | 说明 | 是否直接修改转化后文本 |
|---|---|---|
| AUTO | 确定性较高，可自动转化 | 是 |
| CANDIDATE | 生成候选，供后续参考 | 否 |
| REVIEW | 高风险，必须人工确认 | 否 |
| BLOCK | 阻止当前字段或整条结果继续进入自动流程 | 否 |

### 7.3.1 AUTO适用范围

适用于：

- 中文数字转阿拉伯数字；
- “乘、乘以、X、*”统一为“×”；
- 明确医学同音词；
- 明确重复文本清理；
- 明确格式统一。

### 7.3.2 REVIEW或BLOCK适用范围

涉及以下内容时，不得自动确认：

- 真实数字发生改变；
- 左右侧冲突；
- 否定词变化；
- 内膜A/B/C分型不明确；
- 无回声、有回声、强回声等属性冲突；
- 移植、取消移植、麻醉、血糖及药物剂量；
- ASR整条未转写；
- 数字无法可靠拆分；
- 输出循环或异常超长。

## 7.4 转化记录

每一次转化必须保存独立记录。

```json
{
  "conversion_id": "CV000001",
  "case_id": "A018179",
  "raw_span": "肉卵巢",
  "converted_span": "右卵巢",
  "raw_start": 12,
  "raw_end": 16,
  "conversion_type": "medical_term",
  "rule_id": "C001",
  "rule_version": "V1.0",
  "action": "AUTO",
  "confidence": 0.95,
  "review_result": "pending"
}
```

必须保存：

- 原始片段；
- 转化片段；
- 原始文本位置；
- 转化类型；
- 使用规则；
- 规则版本；
- 处理等级；
- 置信度；
- 人工审核结果。

# 8. 功能模块二：ASR转化准确性评估

## 8.1 页面入口

建议在现有ASR审核页面增加：

> **转化评估**

不建议第一期单独建设复杂知识库系统。

页面包含三份文本：

```text
原始ASR ｜ 转化后ASR ｜ 人工标准ASR
```

## 8.2 页面布局

### 8.2.1 三栏对比区

| 原始ASR | 转化后ASR | 人工标准ASR |
|---|---|---|
| ASR模型原始输出 | 经词库和规则处理结果 | 人工审核后的标准文本 |

### 8.2.2 转化片段列表

每个片段展示：

- 原始片段；
- 转化结果；
- 转化类型；
- 处理动作；
- 规则ID；
- 规则版本；
- 转化原因；
- 风险等级；
- 系统初判；
- 人工审核结果。

### 8.2.3 高亮规则

建议使用以下状态标识：

| 状态 | 展示含义 |
|---|---|
| 绿色 | 转化正确 |
| 红色 | 转化错误 |
| 黄色 | 候选或待复核 |
| 蓝色 | 纯数字或格式标准化 |
| 橙色 | 应转未转 |
| 灰色 | 未发生变化 |

颜色只作为辅助，页面仍需显示文字状态，避免仅依赖颜色理解。

## 8.3 系统自动初判

系统通过比较：

```text
原始ASR
转化后ASR
人工标准ASR
```

自动给出初步判断。

### 示例一：正确转化

```text
原始：肉卵巢
转化：右卵巢
标准：右卵巢
```

系统初判：`转化正确`

### 示例二：错误转化

```text
原始：9.2
转化：5.2
标准：9.2
```

系统初判：`错误转化`

### 示例三：漏转

```text
原始：尾生欠军
转化：尾生欠军
标准：回声欠均
```

系统初判：`应转未转`

### 示例四：过度转化

```text
原始：右卵巢
转化：左卵巢
标准：右卵巢
```

系统初判：`不应转化`

## 8.4 人工审核操作

审核人员可对转化片段执行：

- 转化正确；
- 转化错误；
- 转化不完整；
- 应转未转；
- 不应转化；
- 候选正确；
- 候选错误；
- 无法判断；
- 需回听原音；
- 忽略纯格式差异。

为减少人工工作量：

- 系统先自动判断；
- 审核人员重点处理有争议片段；
- 已明确匹配标准ASR的低风险转换可默认判定为正确；
- 涉及数字、左右侧、否定词和临床决策的片段必须明确确认。

## 8.5 转化准确性指标

### 8.5.1 转化准确率

`正确转化数量 ÷ 全部实际转化数量`

### 8.5.2 错误转化率

`错误转化数量 ÷ 全部实际转化数量`

需额外单独统计：

- 数字错误转化率；
- 左右侧错误转化率；
- 否定词错误转化率；
- 内膜分型错误转化率；
- 医疗决策错误转化率。

### 8.5.3 转化覆盖率

`系统正确处理的ASR错误数量 ÷ 人工实际纠正的ASR错误总数`

### 8.5.4 漏转率

`应转未转数量 ÷ 人工实际纠正的ASR错误总数`

### 8.5.5 过度转化率

`不应转化但被系统修改的数量 ÷ 全部实际转化数量`

### 8.5.6 候选命中率

`人工最终采用的候选数量 ÷ 系统生成的候选总数`

## 8.6 分类统计

必须分别统计以下类型：

| 类型 | 示例 |
|---|---|
| 医学术语 | 肉卵巢→右卵巢 |
| 数字格式 | 九点二→9.2 |
| 尺寸格式 | 三九乘三零→39×30 |
| 数字拆分 | 6035→60×35 |
| 字段名称 | 左两条大小→左卵巢大小 |
| 超声属性 | 五回声→无回声 |
| 左右归属 | 左卵巢、右卵巢 |
| 否定表达 | 未见、无、有 |
| 医疗决策 | 取消移植、继续移植 |
| 噪声处理 | 重复输出、无关对话 |

# 10. 功能模块四：人工标准ASR反哺词库

## 10.1 功能目标

将人工审核产生的标准ASR转换为可复用的候选词及候选规则。

核心原则：

> 人工审核结果只生成候选，未经人工审核不得自动进入正式词库。

## 10.2 审核完成后的处理流程

人工点击“审核完成”后，系统执行：

1. 保存原始ASR；
2. 保存转化后ASR；
3. 保存人工标准ASR；
4. 保存审核人员及审核时间；
5. 异步比较原始ASR与标准ASR；
6. 抽取差异片段；
7. 自动识别差异类型；
8. 过滤无价值差异；
9. 生成候选词或候选规则；
10. 聚合相同候选；
11. 进入候选审核池。

差异抽取应通过异步任务执行，不阻塞审核页面保存。

## 10.3 差异类型

| 差异类型 | 是否形成候选规则 |
|---|---|
| 医学术语替换 | 是 |
| 高频同音词替换 | 是 |
| 中文数字格式化 | 进入通用数字规则 |
| 尺寸格式化 | 进入数字规则 |
| 标点调整 | 否 |
| 删除闲聊 | 可形成噪声规则候选 |
| 真实数值修改 | 否，仅形成高风险记录 |
| 左右侧修改 | 高风险候选，不自动发布 |
| 否定词修改 | 高风险候选 |
| 原ASR漏识整句 | 否 |
| 人工医学总结或润色 | 否 |

## 10.4 差异数据结构

```json
{
  "diff_id": "D000001",
  "case_id": "A018179",
  "raw_span": "肉卵巢",
  "reviewed_span": "右卵巢",

  "raw_end": 4,
```

## 10.5 候选聚合

系统按以下维度聚合候选：

- 原始表达；
- 标准表达；
- ASR模型；
- 业务场景；
- 上下文模式。

- 总出现次数；
- 涉及病历数；

- 首次出现时间；
- 最近出现时间；
- 是否存在多个标准结果；
- 是否与正式词库冲突。

# 12. Synonyms参考范围

Synonyms不进入第一期实时自动转化链路。

仅保留以下两个参考用途。

## 12.1 候选相似聚类

用于提示以下候选可能属于同一标准术语：

```text
回声不匀
回声不均
回声欠均
回声欠均匀
```

系统可提示管理员是否合并。

## 12.2 候选辅助排序

当系统已经通过拼音、医学词库和上下文生成多个候选时，语义相似度可作为低权重辅助分数。

候选排序主要依据：

1. 人工历史纠错一致率；
2. 医学词库命中；
3. 业务场景；
4. 上下文匹配；
5. 拼音相似度；
6. Synonyms语义相似度。

Synonyms不得负责：

- 真实数字纠错；
- 左右侧判断；
- 否定词判断；
- 医疗决策判断；
- 自动决定AUTO或REVIEW。

- 待测试；
- 测试未通过；
- 待发布；
- 灰度中；

- 已回滚；

## 13.2 发布流程

```text
候选审核通过
  ↓
加入待发布版本
  ↓
生成版本差异
  ↓
执行历史测试集
  ↓

  ↓
确认测试结果
  ↓
灰度发布
  ↓
正式发布
```

## 13.3 发布前校验

新版本不得：

- 新增真实数字错误；
- 新增左右侧错误；
- 新增否定词错误；
- 新增临床决策错误；
- 显著降低历史正确样本准确率；
- 将REVIEW规则错误提升为AUTO。

## 13.4 回滚

系统应支持：

- 查看当前运行版本；
- 查看历史版本；
- 一键回滚至上一正式版本；
- 记录回滚原因；
- 回滚后重新加载转化服务。

# 14. 功能模块七：LLM效果评估

## 14.1 建设时机

该模块在转化准确性达到基本要求后启用。

## 14.2 三路LLM输入

同一条记录分别运行：

```text
原始ASR → LLM结果A
转化ASR → LLM结果B
```

- 使用同一LLM模型；
- 使用同一提示词版本；
- 使用同一结构化字段定义；
- 使用相同参数；

- 内膜类型；
- 右卵巢大小；

- 右侧卵泡列表；
- 左侧卵泡列表；
- 无回声、强回声等异常影像；
- 取卵、移植、麻醉等操作；
- 抽血、B超、复诊等医嘱。

## 14.4 效果指标

- 总字段准确率；
- 医学术语字段准确率；
- 数字字段准确率；
- 左右侧归属准确率；
- 异常影像字段准确率；
- 高风险字段错误率；
- 待复核率；
- 自动入库率；
- 人工修改字段数量；
- 人工修改字符数量；
- 相比原始ASR的提升幅度；
- 与人工标准ASR基准结果的差距；
- 方案C与方案A的最终字段差距。

# 18. 异常处理

## 18.1 ASR文本为空

- 标记BLOCK；
- 自动重试；
- 重试失败后回退至其他ASR模型或人工回听；
- 不生成词库候选。

## 18.2 循环重复

- 保留首次有效片段；
- 截断连续重复内容；
- 标记输出异常；
- 进入人工复核；
- 记录模型及出现次数。

## 18.3 转化服务异常

- 不影响原始ASR保存；
- 保留原始ASR继续人工审核；
- 标记“转化失败”；
- 支持后续重新执行转化。

## 18.4 词库规则冲突

- 不自动选择其中一条规则；
- 标记冲突；
- 进入候选审核；
- 正式发布前必须解决。

## 18.5 真实数字变化

- 禁止自动修改；
- 标记最高风险；
- 进入人工复核或回听；
- 不生成固定数字替换规则。

# 22. 最终判断标准

项目是否进入下一阶段，不以词库数量或转化次数为依据，而以以下顺序判断：

```text
第一步：转化是否准确

第三步：转化覆盖率是否有提升空间

第五步：是否减少人工修改和复核
```

只有在转化准确性和高风险控制达到要求后，才建议扩大规则范围并正式接入生产链路。
