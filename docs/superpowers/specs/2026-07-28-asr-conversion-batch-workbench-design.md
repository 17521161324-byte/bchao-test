# ASR 转化评估批次工作台设计

## 目标

将 ASR 转化评估统一为批次工作台。用户从检查记录批量创建评估批次，在批次内按病历号和日期切换记录，对比原始 ASR、转化后 ASR与优化评估中维护的专家标准 ASR。

## 产品入口

- ASR 转化评估首页只展示批次列表。
- 唯一创建入口为“新建批次”。
- 单条评估记录仍作为批次内部数据和兼容 API 存在，但不提供独立前端入口。

## 数据结构

- `AsrConversionBatch` 保存批次名称、日期范围、ASR 来源、规则版本及成功/失败/审校统计。
- `AsrConversionRecord` 按检查记录保存批次明细。
- 没有可用 ASR 的检查记录仍创建批次明细，状态为 `failed`，并记录失败原因，避免用户误以为漏选或漏处理。
- 专家标准 ASR 直接关联 `AsrReferenceTranscript`，不复制或重建人工标准数据。

## 交互

- 新建批次支持日期筛选、病历号搜索、多选检查记录，以及“最新成功 ASR/指定 config_hash”两种来源。
- 批次详情左侧仅显示病历号和日期；失败项显示状态图标。
- 右侧展示原始 ASR、转化后 ASR、专家标准 ASR。
- 转化后文本按转化片段标红；专家标准文本按已有 `reference_annotations` 显示标记。
- 失败记录显示失败原因，不允许执行转化、判定和指标计算。

## 删除规则

删除批次时同步删除该批次专属的转化记录、片段、审校和指标，不影响原始检查记录、ASR 结果或专家标准 ASR。

## 验证

- 后端覆盖最新 ASR、指定指纹、无 ASR、重复检查记录、批次指标和专家标注。
- 前端通过 TypeScript 检查和 Vite 生产构建。
